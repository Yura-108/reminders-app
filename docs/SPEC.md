# Reminders — спецификация приложения

> Живой документ. Всё, что меняется в функционале, сначала правим здесь, потом в коде.

**Стек:** Expo SDK 57 · React Native 0.86 · Expo Router · TypeScript
**Платформа v1:** только Android (разработка и тест через Expo Go на телефоне). Код пишем так, чтобы позже
добавить iOS без переписывания: Android-специфичное держим в отдельных модулях (`features/notifications`).

---

## 1. Обзор

Пользователь записывает задачи и указывает точные дату и время напоминания. В это время телефон показывает
уведомление с вибрацией. Если задача не отмечена выполненной, напоминание повторяется по нарастающей в
течение суток, а в приложении задача помечается как «горящая».

### Глоссарий

| Термин | Значение |
|---|---|
| **Задача** | Текст + дата/время напоминания + статус выполнения |
| **Время напоминания (T)** | Момент, когда приходит первое уведомление |
| **Эскалация** | Повторные уведомления после T, пока задача не выполнена |
| **Горящая задача** | `T` уже прошло, задача не выполнена. Подсвечивается красным, висит вверху списка |
| **Выполненная** | Отмечена пользователем. Все её уведомления отменены |

## 2. Навигация и экраны

### 2.1 Таббар

```
┌───────────────────────────────────────────────────┐
│                                                   │
│                  (контент таба)                   │
│                                                   │
├──────────┬──────────┬─────────┬──────────┬────────┤
│    ☑    │    📅    │  ╭───╮  │    🎂    │   ⚙   │
│  Задачи  │ Календарь│  │ + │  │   Дни    │Настрой-│
│   (3)    │          │  ╰───╯  │ рождения │  ки    │
└──────────┴──────────┴─────────┴──────────┴────────┘
```

- 5 слотов, кнопка «+» **строго по центру**.
- Используем **JS Tabs** (`Tabs` из `expo-router`), а не `NativeTabs` из шаблона: по документации SDK 57
  нативные табы поддерживают только иконку, подпись и бейдж, кастомную кнопку туда не встроить.
- «+» — это `tabBarButton` фиктивного роута `add`. Нажатие **не переключает таб**: оно отменяется
  (`listeners.tabPress` → `e.preventDefault()`) и открывает модалку `task/new`.
- «+» — круглая кнопка акцентного цвета, крупнее остальных иконок, слегка приподнята над таббаром, без подписи.
- Бейдж на табе «Задачи» показывает количество горящих задач (не показывается, если их 0).
- Таб «Дни рождения» в v1 — заглушка («Скоро будет»), логика будет в отдельной спецификации.

### 2.2 Роуты (`src/app/`)

```
src/app/
├── _layout.tsx              Корневой Stack + провайдеры (тема, i18n, инициализация БД и уведомлений)
├── (tabs)/
│   ├── _layout.tsx          Tabs + центральная кнопка «+»
│   ├── index.tsx            Задачи
│   ├── calendar.tsx         Календарь
│   ├── add.tsx              Фиктивный роут под «+» (никогда не отображается)
│   ├── birthdays.tsx        Дни рождения (заглушка)
│   └── settings.tsx         Настройки
└── task/
    ├── new.tsx              Создание задачи (модалка). Параметр ?date=YYYY-MM-DD — предзаполнение
    ├── [id].tsx             Редактирование задачи (модалка)
```

`(tabs)` — группа: скобки не попадают в URL, это просто способ сгруппировать экраны под один layout.

Удаляем из шаблона на этапе 1: `src/app/explore.tsx`, `src/components/app-tabs*.tsx`,
`animated-icon*`, `web-badge.tsx`, `hint-row.tsx`, `external-link.tsx`, `ui/collapsible.tsx` и неиспользуемые
картинки (`assets/images/tabIcons/`).

## 3. Функционал по экранам

### 3.1 Задачи (`(tabs)/index.tsx`)

```
┌─────────────────────────────────┐
│ Задачи                          │
├─────────────────────────────────┤
│ ⚠ Уведомления выключены [Вкл.] │  ← баннер, только если нет разрешения
│                                 │
│ 🔥 ГОРЯЩИЕ (2)                  │
│ ┌─────────────────────────────┐ │
│ │ ○ Позвонить врачу           │ │
│ │   вчера, 18:00         🔥   │ │
│ └─────────────────────────────┘ │
│ СЕГОДНЯ                         │
│ ┌─────────────────────────────┐ │
│ │ ○ Забрать посылку           │ │
│ │   19:30                     │ │
│ └─────────────────────────────┘ │
│ ЗАВТРА                          │
│ ПОЗЖЕ                           │
│ ▸ ВЫПОЛНЕННЫЕ (5)               │  ← свёрнута по умолчанию
└─────────────────────────────────┘
```

**Секции** (пустые секции не показываются):

| Секция | Условие | Сортировка |
|---|---|---|
| Горящие | `remindAt < now` и не выполнена | от самой старой |
| Сегодня | сегодня, `remindAt >= now`, не выполнена | по времени ↑ |
| Завтра | завтра, не выполнена | по времени ↑ |
| Позже | после завтра, не выполнена | по дате ↑ (с заголовком даты в карточке) |
| Выполненные | выполнена | по `completedAt` ↓; свёрнута; очищается раз в неделю (см. 5.4) |

**Карточка задачи:**
- круглый чекбокс слева: тап → выполнено/не выполнено (с вибро-откликом `expo-haptics`).
  При отметке галочка появляется с анимацией, текст зачёркивается, задача ~0,7 с остаётся на месте
  (повторный тап в это время отменяет отметку), затем плавно уезжает в «Выполненные». Снятие отметки — сразу;
- текст задачи (максимум 2 строки, обрезка многоточием);
- время (для «Сегодня»), «завтра, 9:00», «12 окт, 9:00» или относительное «вчера, 18:00» (для горящих);
- горящая: красная полоска слева + иконка 🔥;
- выполненная: текст зачёркнут и приглушён.

**Жесты:**
- тап по карточке → `task/[id]` (редактирование);
- свайп влево → удалить: карточка остаётся сдвинутой на красном фоне и плавно схлопывается по высоте.
  Внизу на 4 секунды появляется снэкбар «Задача удалена · Отменить»;
- свайп вправо → выполнено (та же анимация с паузой, что у чекбокса) / вернуть в работу.

**Пустое состояние:** иллюстрация/иконка + «Задач пока нет. Нажмите +, чтобы добавить первую».

### 3.2 Модалка задачи (`task/new`, `task/[id]`)

```
┌─────────────────────────────────┐
│ ✕   Новая задача      Сохранить │
├─────────────────────────────────┤
│ ┌─────────────────────────────┐ │
│ │ Что нужно сделать?          │ │  ← многострочное поле, автофокус
│ │                             │ │
│ └─────────────────────────────┘ │
│                          0/500  │
│                                 │
│ НАПОМНИТЬ                       │
│ ┌─────────────┐ ┌─────────────┐ │
│ │ 📅 Ср, 8 окт│ │ 🕐 19:30    │ │  ← тап → системный DatePicker / TimePicker
│ └─────────────┘ └─────────────┘ │
│ [Через час] [Сегодня 14:00] [Сегодня 18:00]
│ [Завтра 8:00] [Завтра 13:00]    │  ← быстрые чипы
│                                 │
│ (только при редактировании)     │
│ [ ✓ Выполнено ]                 │
│ [ 🗑 Удалить  ]                 │
└─────────────────────────────────┘
```

**Поведение:**
- Значение по умолчанию для новой задачи: ближайший следующий час (сейчас 14:20 → 15:00).
  Если открыто из календаря с выбранным днём — этот день и 9:00 (или следующий час, если день сегодняшний).
- Быстрые чипы: «Через час», «Сегодня 14:00», «Сегодня 18:00», «Завтра 8:00», «Завтра 13:00».
  Чипы на сегодня скрываются, когда их время прошло. Выбранный чип подсвечивается.
- Дата и время — системные диалоги Android (`@react-native-community/datetimepicker`, режимы `date` и `time`).
  Формат времени 24ч/12ч берём из настроек системы.
- **Валидация:**
  - текст обязателен (после `trim`), максимум 500 символов;
  - время напоминания не может быть в прошлом. Ошибка: «Выберите время в будущем»;
  - при редактировании горящей задачи можно сохранить только текст, не трогая время. Если время изменено,
    оно тоже должно быть в будущем.
- «Сохранить» неактивна, пока форма невалидна.
- Закрытие с несохранёнными изменениями (✕ или системная кнопка «Назад») → диалог «Отменить изменения?».
- При сохранении: запись в БД → перепланирование уведомлений → закрытие модалки.
- При первом сохранении задачи запрашиваем разрешение на уведомления (см. 4.4).
- Клавиатура не должна перекрывать поля (`KeyboardAvoidingView` / прокрутка).
- «Удалить» → подтверждение «Удалить задачу?». «Выполнено» → отметить выполненной и закрыть.
- У горящей задачи дополнительно есть кнопка «Перенести»: открывает то же меню, что и из уведомления (см. 4.5).

## 4. Уведомления

Используем **локальные** уведомления `expo-notifications`.

**Только в собственной сборке (development build / APK), не в Expo Go.** В SDK 57 пакет на Android в Expo Go
падает уже при импорте (при загрузке регистрирует слушатель push-токена, а push из Expo Go убран), хотя
документация говорит, что локальные уведомления там работают. Поэтому пакет подгружается через
`features/notifications/module.ts` только вне Expo Go; в Expo Go уведомления отключены, остальное приложение работает.

### 4.1 Расписание и эскалация

Для невыполненной задачи с временем `T` планируем до 7 уведомлений (триггер `DATE`):

| № | Когда | Текст (ru) |
|---|---|---|
| 1 | T | «Забрать посылку» / «Напоминание · 19:30» |
| 2 | T + 5 мин | «🔥 Забрать посылку» / «Просрочено · было на 19:30» |
| 3 | T + 15 мин | то же |
| 4 | T + 30 мин | то же |
| 5 | T + 1 ч | то же |
| 6 | T + 2 ч | то же |
| 7 | T + 4 ч | то же. Больше не напоминаем |

- Смещения считаются **от T**, а не от предыдущего уведомления. Если нужны интервалы между уведомлениями
  (5, 15, 30 мин, 1, 2, 4 ч → последнее примерно через 8 ч), это меняется одной константой
  `ESCALATION_OFFSETS` в `features/notifications/schedule.ts`.
- Если переключатель «Повторять, пока не выполнено» выключен, планируется только №1.
- Все уведомления задачи используют один `identifier`-префикс (`<taskId>:<n>`), поэтому любое из них
  можно найти и отменить.
- После 7-го уведомления задача остаётся горящей в приложении бессрочно, пока её не выполнят или не удалят.

### 4.2 Жизненный цикл

| Событие | Действие с уведомлениями |
|---|---|
| Создание | запланировать все будущие из расписания |
| Изменение времени или текста | отменить все → запланировать заново |
| Выполнено | отменить все + убрать уже показанные из шторки |
| Вернуть в работу | если `T` в будущем — запланировать; если в прошлом — уведомлений нет, задача горящая |
| Удаление | отменить все + убрать показанные. При «Отменить» в снэкбаре — запланировать снова |
| Перенести (15м / 30м / 1ч / своё время) | отменить все + убрать показанные → T = новое время → запланировать полный цикл заново |
| Старт приложения | синхронизация: сверить `getAllScheduledNotificationsAsync()` с БД, удалить «сиротские», добавить недостающие |

### 4.3 Вибрация (каналы Android)

На Android 8+ звук и вибрация задаются **каналом уведомлений**, а настройки канала после создания изменить
нельзя (это ограничение Android, указано в документации SDK 57). Поэтому:

- при старте создаём 4 канала (если их ещё нет):

  | Канал | Паттерн (мс) |
  |---|---|
  | `reminders-none` | без вибрации |
  | `reminders-short` | `[0, 250]` |
  | `reminders-long` | `[0, 1000]` |
  | `reminders-pulse` | `[0, 200, 150, 200, 150, 200]` |

- важность каналов `HIGH` (уведомление всплывает поверх экрана);
- при планировании указываем `channelId` по текущей настройке вибрации;
- смена настройки → перепланировать все будущие уведомления на новый канал.

Пользователь также может изменить канал в системных настройках Android. Это нормально, мы с этим не спорим.

### 4.4 Разрешения

- Android 13+ требует явного согласия. Системный диалог появляется только после создания хотя бы одного канала.
- Спрашиваем **при первом сохранении задачи**, а не при запуске: так понятно, зачем нужно разрешение.
- Отказ → задача всё равно сохраняется, на списке появляется баннер «Уведомления выключены» с кнопкой,
  которая открывает системные настройки приложения (`Linking.openSettings()`).
- Статус разрешения перепроверяем при каждом возврате приложения на передний план (`AppState`).

### 4.5 Взаимодействие с уведомлением

```
┌─────────────────────────────────────┐
│ 🔔 Reminders · сейчас               │
│ Забрать посылку                     │
│ Сегодня, 19:30                      │
│ ─────────────────────────────────── │
│   ВЫПОЛНЕНО          ПЕРЕНЕСТИ      │
└─────────────────────────────────────┘
```

У каждого уведомления (и первого, и повторов эскалации) две кнопки, заданные через категорию
`setNotificationCategoryAsync('task-reminder', [...])`:

**«Выполнено»** (`opensAppToForeground: false`, приложение не открывается)
- задача отмечается выполненной (`completedAt = now`);
- все оставшиеся запланированные уведомления задачи отменяются;
- уведомление убирается из шторки (`dismissNotificationAsync`), как и ранее показанные повторы этой задачи.

**«Перенести»** (`opensAppToForeground: true`)

Ограничение Android: внутри уведомления нельзя показать меню, кнопки там только плоские (максимум 3).
Поэтому «Перенести» открывает приложение **сразу на маленьком нижнем меню** (bottom sheet) поверх текущего
экрана, без перехода в редактор задачи:

```
┌─────────────────────────────────┐
│          (затемнение)           │
├─────────────────────────────────┤
│ Перенести «Забрать посылку»     │
│                                 │
│ [ 15 минут ]    [ 30 минут ]    │
│ [ 1 час    ]    [ Задать время ]│
│                                 │
│            Отмена               │
└─────────────────────────────────┘
```

| Кнопка | Новое время T |
|---|---|
| 15 минут | `now + 15 мин` |
| 30 минут | `now + 30 мин` |
| 1 час | `now + 1 ч` |
| Задать время | открывается системный DatePicker → TimePicker (дата по умолчанию сегодня); время должно быть в будущем |

- Отсчёт идёт **от момента нажатия** (`now`), а не от старого T.
- После выбора: T обновляется в БД, старое расписание отменяется, эскалация планируется заново от нового T
  (полный цикл: T, +5м, +15м …), уведомление убирается из шторки, меню закрывается, короткий тост
  «Перенесено на 19:45».
- «Отмена» или свайп вниз → ничего не меняется, уведомление тоже убирается (повторы эскалации продолжают идти
  по старому расписанию).
- Роут меню: `src/app/task/snooze/[id].tsx` с `presentation: 'formSheet'` (нижний лист). Если оно открыто из
  уведомления при закрытом приложении, под ним открывается таб «Задачи».
- То же меню доступно и внутри приложения: пункт «Перенести» у горящей задачи (кнопка в модалке редактирования).

**Тап по самому уведомлению** (не по кнопке) → открыть приложение на `task/[id]`.

**Технически:**
- «Выполнено» при свёрнутом/закрытом приложении обрабатывает фоновая задача `expo-task-manager`
  (`features/notifications/background-task.ts`). Android запускает JS без UI только ради неё, поэтому она
  объявляется в собственной точке входа `index.ts` (`"main": "index.ts"`) до `expo-router/entry`.
  Обработка идемпотентна (`setDone(id, true)`): если приложение живо, ответ придёт ещё и в слушатель.
- При возврате приложения на передний план задачи перечитываются из БД — их могла изменить фоновая задача.
- Ответы в открытом приложении обрабатываются в одном месте, `features/notifications/use-notification-responses.ts`:
  `addNotificationResponseReceivedListener` + `getLastNotificationResponseAsync()` при холодном старте
  (приложение было закрыто). Различаем по `actionIdentifier`: `done`, `snooze` или тап по уведомлению.
- В `content.data` уведомления кладём `{ taskId }`, чтобы найти задачу.
- Если уведомление пришло, пока приложение открыто, оно всё равно показывается (`setNotificationHandler`),
  а список обновляется.

### 4.6 Известные ограничения v1

- **Точность.** Для точного времени на Android 12+ нужно разрешение `SCHEDULE_EXACT_ALARM`
  (добавляется в `app.json` → `android.permissions`, работает в собственной сборке, этап 8).
- **Лимит.** Android ограничивает число запланированных будильников на приложение (около 500).
  7 уведомлений × N задач: при 70+ активных задачах эскалацию планируем только для ближайших задач,
  остальные дополняем при синхронизации на старте.
- Производители (Xiaomi, Huawei, Samsung) могут убивать фоновые задачи. На экране настроек можно добавить
  подсказку про отключение оптимизации батареи (этап 8).

## 5. Данные

### 5.1 Хранилище

- **Задачи** — `expo-sqlite` (есть в Expo Go).
- **Настройки** — `expo-sqlite/kv-store` (синхронный key-value, API как у `localStorage`).
- Миграции схемы — через `PRAGMA user_version`: при старте выполняем недостающие шаги по порядку.

### 5.2 Модель задачи

```ts
type Task = {
  id: string;              // uuid (expo-crypto randomUUID)
  title: string;           // 1..500 символов
  remindAt: string;        // ISO 8601 в UTC, например "2026-10-08T16:30:00.000Z"
  completedAt: string | null;
  notificationIds: string[]; // id запланированных уведомлений
  createdAt: string;
  updatedAt: string;
};
```

SQL:

```sql
CREATE TABLE tasks (
  id TEXT PRIMARY KEY NOT NULL,
  title TEXT NOT NULL,
  remind_at TEXT NOT NULL,
  completed_at TEXT,
  notification_ids TEXT NOT NULL DEFAULT '[]',
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
CREATE INDEX idx_tasks_remind_at ON tasks(remind_at);
```

### 5.3 Производные статусы (не хранятся, вычисляются)

```ts
type TaskStatus = 'done' | 'burning' | 'upcoming';
// done     — completedAt !== null
// burning  — !done && remindAt <= now
// upcoming — !done && remindAt > now
```

`now` обновляется раз в минуту, пока приложение открыто, и при каждом возврате на передний план
(`AppState` → `active`). Так задача становится горящей без перезапуска.

### 5.4 Очистка

Раз в неделю, **в полночь с воскресенья на понедельник** (местное время), удаляются все задачи,
выполненные до этого момента. Неделя начинается с чистого списка выполненных.

Это не фоновая задача: фоновые задачи Android не запускаются в точное время, а некоторые прошивки их убивают.
Вместо этого очистка «догоняет» при каждом удобном случае, и для пользователя результат тот же:
- при запуске приложения (до скрытия сплэша, поэтому старые задачи не мелькают);
- при возврате приложения на передний план;
- ровно в полночь, если приложение в этот момент открыто (по ежеминутному тику `useNow`).

Граница — понедельник 00:00 текущей недели: задача, выполненная в воскресенье в 23:50, удалится в 00:00,
выполненная в понедельник в 00:01 — останется до следующего понедельника. Невыполненные задачи не трогаются.
В будущем день очистки может стать настройкой.

### 5.5 Настройки

```ts
type Settings = {
  theme: 'system' | 'light' | 'dark';
  language: 'system' | 'ru' | 'en';
  vibration: 'none' | 'short' | 'long' | 'pulse';
  escalation: boolean;
};
```

### 5.6 Состояние в UI

**Zustand**: стор без провайдера и бойлерплейта, хуки как в обычном React. Слои:

```
UI (экраны, компоненты)
   ↓ хуки useTasks(), useSettings()
Store (zustand) — данные в памяти + действия: addTask, updateTask, toggleDone, deleteTask, restoreTask
   ↓
Repository (SQL) + Notifications service
```

Компоненты не ходят в SQL и `expo-notifications` напрямую, только через действия стора.

## 6. Тема и локализация

### 6.1 Тема

- Цветовые токены — в `src/constants/theme.ts` (уже есть в шаблоне, расширяем):
  `text`, `textSecondary`, `background`, `card`, `border`, `primary`, `onPrimary`, `danger`, `success`, `muted`.
- Хук `useTheme()` (`src/hooks/use-theme.ts`, уже есть) возвращает цвета текущей темы.
- Выбор темы в настройках → `Appearance.setColorScheme('light' | 'dark' | null)`. `null` = как в системе.
  После этого `useColorScheme()` во всём приложении отдаёт выбранную тему.
- Навигационная тема (`ThemeProvider` из `expo-router`) и цвет статус-бара переключаются вместе с темой.
- `app.json` уже содержит `"userInterfaceStyle": "automatic"`.

### 6.2 Языки

- `i18next` + `react-i18next` (знакомый по вебу `useTranslation()`), `expo-localization` для языка системы.
- Словари: `src/i18n/ru.ts`, `src/i18n/en.ts`. Типизация ключей через `en.ts` как эталон: опечатка в ключе
  ловится TypeScript-ом.
- Множественное число: i18next умеет русские формы (`задача / задачи / задач`).
- Даты и время — `Intl.DateTimeFormat` с текущей локалью. Относительные «сегодня/завтра/вчера» — через словарь.
- Локаль `react-native-calendars` (`LocaleConfig`) переключается вместе с языком.
- Тексты уведомлений фиксируются в момент планирования, поэтому смена языка → перепланировать будущие уведомления.

## 9. Шпаргалка «React → React Native»

| В вебе | В React Native |
|---|---|
| `<div>` | `<View>` |
| `<span>`, `<p>` | `<Text>`. **Любой текст обязан быть внутри `<Text>`**, иначе будет ошибка |
| `<img>` | `<Image>` из `expo-image` |
| `<input>` | `<TextInput>` |
| `<button onClick>` | `<Pressable onPress>` |
| CSS-файлы, классы | `StyleSheet.create({...})`, стили — объекты, без каскада и наследования (кроме Text в Text) |
| `display: flex` по умолчанию нет | Всё уже flex, и `flexDirection` по умолчанию **column** |
| `px`, `rem` | числа без единиц (density-independent pixels) |
| `.map()` для длинных списков | `FlatList` / `SectionList`: рендерят только видимое |
| `overflow: auto` | `<ScrollView>` |
| React Router | Expo Router: файл = экран, `router.push('/task/123')`, `<Link href>` |
| `localStorage` | `expo-sqlite/kv-store` |
| DevTools | в терминале `j` (дебаггер), встряхнуть телефон → меню разработчика, `r` → перезагрузка |

Мобильная специфика, о которой легко забыть:
- **Безопасные зоны:** вырез камеры и системная панель. `SafeAreaView` / `useSafeAreaInsets`.
- **Клавиатура** перекрывает поля → `KeyboardAvoidingView` или прокрутка.
- **Кнопка «Назад» Android** — экраны и модалки должны корректно на неё реагировать.
- **Размер тач-зоны** ≥ 44×44 — пальцы толще курсора (`hitSlop`).

## 10. Этапы реализации

Каждый этап заканчивается: `npx expo lint` + `npx tsc --noEmit` без ошибок + ручная проверка на телефоне
по чек-листу этапа.

| # | Этап | Готово, когда |
|---|---|---|
| 1 | **Каркас.** Удалить шаблонный код, роуты из 2.2, JS-табы с центральной «+», пустые экраны, модалка открывается по «+» | 5 слотов, «+» по центру открывает модалку, табы переключаются |
| 2 | **Тема и i18n.** Токены цветов, `useTheme`, i18next со словарями ru/en, все тексты через `t()` | Тема и язык выбираются в Настройках, сохраняются и сразу меняют весь UI |
| 3 | **Данные.** SQLite, миграции, репозиторий, zustand-стор, список с секциями, временная кнопка «добавить тестовую задачу» | Задачи переживают перезапуск, секции и горящие считаются верно |
| 4 | **Модалка задачи.** Форма, пикеры даты/времени, чипы, валидация, редактирование, удаление со снэкбаром, выполнено, свайпы | Полный CRUD без уведомлений |
| 5 | **Уведомления.** Каналы, разрешения, баннер, планирование с эскалацией, отмена, кнопки «Выполнено» / «Перенести», меню переноса, deep link, синхронизация | Уведомление приходит вовремя, повторяется, «Выполнено» из шторки работает, «Перенести» открывает меню и переносит |
| 6 | **Календарь.** Сетка, точки, задачи дня, предзаполнение даты при «+» | Календарь синхронен со списком |
| 7 | **Настройки.** Тема, язык, вибрация с «Попробовать», эскалация, статус разрешения, версия; перепланирование при смене | Все настройки сохраняются и применяются сразу |
| 8 | **Полировка и сборка.** Haptics, пустые состояния, иконка, сплэш, EAS development build, `SCHEDULE_EXACT_ALARM`, проверка на Doze | Приложение стабильно работает как установленный APK |
